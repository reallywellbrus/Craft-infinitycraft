# Craft Modes

Платформа, где любой игрок придумывает свой **Infinite Craft**: выбирает, что получится из каждой пары элементов, собирает собственный набор и публикует режим, в который играют другие.

Проект специально сделан без сборки — обычные HTML, CSS и JavaScript. Открывается двойным кликом с диска и без изменений публикуется на GitHub Pages.

## Что уже работает

- **Редактор режима.** Начинается с четырёх стихий: Вода, Огонь, Ветер, Земля.
- **Крафт с выбором.** Соединяете два элемента — игра спрашивает, что получится:
  - **придумать новый** (эта вкладка открыта по умолчанию): ввести название, получить подобранный эмодзи и при желании заменить его вручную;
  - выбрать **уже существующий** элемент режима на соседней вкладке.
  - Два ингредиента исчезают со стола, вместо них появляется результат — как в Infinite Craft.
- **Умный подбор эмодзи.** «Диван» → 🛋️, «Кораблик» → 🚢, «Гриб» → 🍄. Если ничего не подошло — ✨, его можно заменить.
- **Игра по режиму.** Открываются только четыре базовых элемента; остальные появляются по правилам режима. Прогресс сохраняется отдельно для каждого режима.
- **Каталог режимов.** Свои режимы — сразу; после подключения Supabase появляется общий каталог с поиском по названию и автору, лайками и кнопкой «Играть».
- **Чужие режимы защищены:** в них нельзя открыть полный список рецептов или опубликовать режим от своего имени. Доступны игра, ссылка и очистка стола.
- **Публикация.** Название, описание, автор, эмодзи режима.
- **Обмен без сервера.** Режим можно скачать файлом `.json`, загрузить обратно или отправить ссылкой `#share=…`.
- **Фишку можно вернуть на панель** — она исчезнет со стола, но останется в коллекции и правилах режима.
- **Кнопка «Очистить»** убирает фишки со стола, но не удаляет элементы режима и открытую коллекцию.
- **Книга рецептов режима.** Кнопка «📖 Рецепты» показывает все правила: пару, результат и статус в игре; есть поиск.
- **Клавиатура эмодзи.** Кнопка 😊 у поля эмодзи открывает поиск по русским названиям и категории: смайлы, животные, еда, природа, предметы, активности, места, символы.
- **Жалобы.** Кнопка 🚩 на карточке режима и в меню. Жалоба уходит в Supabase, админ видит её на отдельной странице `/admin.html`.
- **Фильтр нежелательных слов.** Проверяет названия элементов, названия и описания режимов, имя автора и импортируемые файлы. Режимы с плохими словами не попадают в каталог.
- **Адаптивная вёрстка.** На телефоне панель элементов переезжает под стол.

## Быстрый старт

Откройте `index.html` двойным кликом. Если браузер ограничивает сохранения на `file://`, запустите локальный сервер:

```bash
python -m http.server 8000
```

и откройте `http://localhost:8000`.

**Создать режим:** «＋ Создать режим» → соедините пару на столе → выберите готовый элемент или вкладку «Придумать новый» → «💾 Сохранить режим» → задайте название и автора → «🌐 Опубликовать».

**Играть:** на главной нажмите на карточку режима. Кнопка «↺ Заново» очищает прогресс именно этого режима.

## Формат режима

```json
{
  "format": "craft-modes/v1",
  "name": "Диванная вселенная",
  "description": "Из огня и воды получается мебель",
  "author": "Игорь",
  "emoji": "🛋️",
  "hue": 20,
  "base": [
    { "id": "water", "name": "Вода", "emoji": "💧", "hue": 200 }
  ],
  "elements": [
    { "id": "x-1", "name": "Диван", "emoji": "🛋️", "hue": 20 }
  ],
  "rules": [["water", "fire", "x-1"]]
}
```

Правило — это пара `a + b = result`. Элементы и правила проверяются при сохранении: нельзя сослаться на несуществующий элемент, одна пара не может дать два разных результата. Ограничения на размер: 500 своих элементов и 2000 правил.

## Каталог на сервере

GitHub Pages умеет отдавать только статические файлы, поэтому **общий каталог, лайки и поиск у всех игроков** требуют внешней базы. В проекте уже есть клиент и схема для бесплатного [Supabase](https://supabase.com).

Сейчас без настройки работает локальный режим: свои режимы, файлы, ссылки и лайки хранятся в `localStorage`. Если вписать адрес Supabase, каталог начнёт загружаться с сервера.

В этой копии проекта Supabase уже подключён — URL и publishable key лежат в [js/config.js](js/config.js). Для нового проекта достаточно заменить их на свои.

### Подключение за 4 шага

1. Создайте бесплатный проект на supabase.com.
2. Откройте **SQL Editor → New query**, вставьте [db/schema.sql](db/schema.sql) и нажмите **Run**.
3. Откройте **Settings → API** и скопируйте **Project URL** и **anon public key**.
4. Впишите их в [js/config.js](js/config.js) — тогда каталог увидят **все посетители сайта**. После перезагрузки сайт сам подключится к каталогу.

```js
window.CRAFT_SUPABASE = {
  url: 'https://abcdefgh.supabase.co',
  anonKey: 'eyJhbGciOiJIUzI1NiIs...',
};
```

`config.js` загружается до `storage.js`, поэтому после перезагрузки сайт сам подключится к каталогу. Если оставить поля пустыми, игра работает локально.

Схема создаёт:

- таблицу `modes` — опубликованные режимы;
- таблицу `mode_likes` — один лайк с одного браузера;
- RLS-политики: читать и добавлять режимы может любой, менять и удалять — только владелец проекта через админку;
- функцию `like_mode`, которая пересчитывает лайки на сервере.

**Важно про безопасность.** `anon key` публичный по задумке Supabase, его можно держать во фронтенде. **Никогда не вставляйте `service_role key`** в браузерный код. Сейчас публиковать режим может любой без регистрации — для открытого каталога это удобно, но требует модерации. Для продакшена добавьте Supabase Auth, rate limiting и удаление спама.

Фильтр нежелательных слов работает в браузере: он не даёт сохранить или опубликовать плохой текст через интерфейс, но при прямом запросе к API его можно обойти. Для строгой модерации продублируйте проверку на сервере или проверяйте новые режимы вручную.

`admin.html` не содержит пароля или данных жалоб — это только форма входа. Защита находится в Supabase Auth и RLS-политиках. Если `admin.html` не загружать, админ-интерфейса просто не будет; жалобы можно смотреть в Supabase Table Editor.

Схема также не даёт клиенту подставить свой счётчик лайков: при вставке режима `likes` принудительно обнуляется триггером, а считает их только функция `like_mode`.

## Жалобы и админка

Кнопка **🚩** есть на каждой карточке режима и в меню игры. Жалоба сохраняется в таблице `reports` в Supabase; причина — плохие слова, спам, сломанный режим или другое.

Чтобы жалобы действительно приходили:

1. Выполните **обновлённый** [db/schema.sql](db/schema.sql) — он создаёт таблицу `reports` и политики.
2. В Supabase откройте **Authentication → Users → Add user** и создайте админа с email и паролем. Подтвердите email, если включено подтверждение.
3. В **Authentication → Providers → Email** выключите **Allow new users to sign up** — иначе любой зарегистрированный пользователь сможет читать жалобы.
4. Откройте `https://ВАШ_САЙТ/admin.html` и войдите этим аккаунтом.

Доступ к жалобам и удалению режимов даёт вход через Supabase Auth. Поэтому `admin.html` можно загружать: без email и пароля страница покажет только форму входа.

Админ-страница умеет показывать жалобы, закрывать их, возвращать в работу и **удалять режим с сервера**. Удаление режима не стирает жалобу: она остаётся в архиве закрытой. Пароль в коде не хранится: вход идёт через Supabase Auth, токен живёт в `sessionStorage` вкладки.

**Секретный вход:** на главной странице наберите на клавиатуре **`8 7 4 2 3`** (пробелы между цифрами допустимы). Откроется `admin.html` с формой входа. Пароль администратора вводится там и проверяется Supabase; в JavaScript он не записан. Код не срабатывает, когда курсор стоит в поле поиска или другом текстовом поле.

Если сервер не настроен, жалоба сохраняется только в `localStorage` браузера — админ её не увидит.

## Публикация на GitHub Pages

1. Создайте **публичный** репозиторий (на бесплатном плане Pages работает только в публичных).
2. Загрузите файлы проекта, кроме папки `tools/`.
3. **Settings → Pages → Deploy from a branch → main → /(root) → Save**.
4. Через 1–10 минут сайт будет доступен по адресу `https://ЛОГИН.github.io/РЕПОЗИТОРИЙ/`.

Файл `.nojekyll` уже добавлен, чтобы GitHub не обрабатывал статику через Jekyll.

## Тесты

В проекте есть браузерный тест на Chrome DevTools Protocol:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/run-test.ps1
```

Проверяются: подбор эмодзи, клавиатура эмодзи, фильтр нежелательных слов, редактор, создание элементов, повторное соединение уже известной пары, исчезновение ингредиентов, очистка стола, книга рецептов с поиском, вкладка «Придумать новый» по умолчанию, запрет чужих рецептов и публикации, удаление фишки перетаскиванием на панель, отправка жалобы, окно выбора «готовый или новый», сохранение режима, запуск игры, открытие по правилам, прогресс после перезагрузки, экспорт/импорт, отказ от чужого JSON и открытие режима по ссылке. Последний прогон — **35/35**, ошибок страницы нет.
